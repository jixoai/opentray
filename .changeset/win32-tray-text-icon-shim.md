win32 text-title tray icon shim (user request 2026-09-24: text-only trays render as transparent slots on Windows while macOS shows the NSStatusItem title — align the platforms). The vendored tray-icon fork now rasterizes the tray title into an RGBA icon through GDI whenever no explicit image icon is set: measured advance width via `GetTextExtentPoint32W` (half-width pairs, full-width CJK, and arbitrary strings all size correctly; 96-logical-px cap with ellipsis), DPI-scaled metrics from the screen DC, Segoe UI semibold with grayscale antialiasing (ClearType subpixel AA breaks the alpha channel), coverage-based alpha with the glyph color following the system taskbar theme (`SystemUsesLightTheme`), and the result rides the crate's own AND-mask-corrected `Icon::from_rgba` path. Explicit icons always win; `set_title` is now a real implementation that re-renders (previously a no-op stub); icon removal falls back to the title render; explorer-restart re-registration paths re-use the effective icon. Theme changes re-render live: the tray window proc handles `WM_SETTINGCHANGE` with the `ImmersiveColorSet` section and refreshes title-based icons on the owner-loop thread. Acceptance on the real machine (user-verified visually) caught two first-draft render defects now fixed: the font was only selected into the measuring DC (DrawTextW silently used GDI's default raster font, producing metric-mismatched glyphs) and the NUL terminator of the crate's `encode_wide` was counted into the DrawTextW length (drawn as a stray half glyph). Runtime and projection layers are untouched — the title already flowed from `text-only` through the projection to `with_title`/`set_title`.
