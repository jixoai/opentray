implement-kernel-webview-foundation self review

The first-stage OpenTray foundation now has a Rust kernel, TypeScript protocol/client contracts, a platform-neutral webview facade, backend adapter atoms, a visible tray example, broker-free TypeScript/WebView human examples, a real WebView visual smoke example, a reusable tray-icon native runtime atom, and native menu event ingress back to OpenTray events.

Review axis Evidence Verdict
Kernel law opentray-core owns surface, tray, lease, projection, backend contract, event routing, and extension registry behavior. Pass
Extension orthogonality Webview commands flow as normal ext-command frames. Core has no webview-specific handler branch. Pass
Backend atom boundary opentray-backend-tray-icon and opentray-backend-ksni implement the same SurfaceBackend contract outside core. Pass
Tray native runtime law NativeTrayIconRuntime owns native tray handles and route tables, while event-loop ownership stays outside the backend. Pass
Human examples cargo run --example native_tray creates a visible tray icon; runtime_boundary and default_unbound remain GUI-free examples; cargo run --example visual_webview opens a real WebView window. Package examples cover TypeScript client frames, WebView extension frames, and protocol parser behavior. Pass
Verification pnpm run verify, OpenSpec validate/check, Rust tests, TypeScript tests/typechecks, and runnable Rust/TypeScript examples plus the visual WebView smoke passed. The manual visual_webview run was observed as a visible window and stabilized on the tao event-loop path. Pass
Known remaining work Native WebView runtime behavior and event-loop queue orchestration are not implemented in this batch. Intentional next layer
