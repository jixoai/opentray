## Requirements

### Requirement: Omitted appIcon SHALL materialize a synthesized glyph default on Darwin

When a caller omits `appIcon` and a Darwin app bundle is materialized by the runtime, the runtime SHALL synthesize a default App icon derived from the caller's `appName` — a first-letter glyph on the continuous-curvature squircle standard — and pass it to bundle materialization, so the Dock and Cmd+Tab never fall through to the operating-system generic executable artwork. The synthesized default SHALL never inherit tray artwork. The Core declared App icon catalog SHALL remain empty when `appIcon` is omitted: `getAppIcon`, `getAppIconVariant`, and `setAppIcon` keep their declared-catalog semantics, and the synthesized default is a carrier materialization concern only. An explicitly declared `appIcon` always wins unchanged; the runtime SHALL NOT substitute a glyph for a declared catalog.

#### Scenario: Omitted appIcon yields a glyph Dock icon after cold launch

- **GIVEN** a caller creates a tray with `appName` and no `appIcon` on Darwin
- **WHEN** the runtime materializes its app bundle and the bundle cold-launches
- **THEN** `Contents/Resources/AppIcon.icns` exists with `CFBundleIconFile` set
- **AND** the icon is a first-letter glyph of `appName` on the shared squircle standard
- **AND** the Core declared catalog stays empty (`getAppIcon` reports no declared assets)

#### Scenario: CJK application names render their first character

- **GIVEN** an `appName` whose first character is outside the embedded default font's coverage
- **WHEN** the default glyph icon is synthesized
- **THEN** the glyph renders the actual first character through the font fallback ladder
- **AND** it SHALL NOT silently degrade to a blank tile or a tofu box without diagnostics

#### Scenario: Repeated starts reuse the cached default icon

- **GIVEN** a default glyph icon was synthesized for an `appName`
- **WHEN** the same caller starts again and the resolved generator identity and recipe are unchanged
- **THEN** materialization reuses the cached asset without re-running generation
- **AND** the bundle manifest icon hash reflects the generated bytes so identity drift re-materializes lawfully

#### Scenario: Generation failure falls back with diagnostics

- **GIVEN** the icon generation stack fails to initialize or encode on a consumer machine
- **WHEN** the runtime materializes the bundle
- **THEN** materialization proceeds without an icon exactly as before this capability
- **AND** the failure is recorded as diagnostics
- **AND** the install or start SHALL NOT be blocked

#### Scenario: Explicit opt-out restores the prior behavior

- **GIVEN** a caller sets the app-bundle default-icon option to disabled
- **WHEN** the runtime materializes the bundle with `appIcon` omitted
- **THEN** no icon is written and no `CFBundleIconFile` is set, matching pre-change behavior

#### Scenario: Read-only reinitialize does not inject a default icon

- **GIVEN** a prebuilt bundle validated under read-only reinitialization with no icon
- **WHEN** the runtime validates that bundle with `appIcon` omitted
- **THEN** the read-only contract wins and no synthesized icon is injected

#### Scenario: Declared appIcon is never replaced by a glyph

- **GIVEN** a caller declares a valid explicit `appIcon`
- **WHEN** the runtime materializes the bundle
- **THEN** the declared assets are written unchanged and no glyph synthesis runs
