## Requirements

### Requirement: One shared icon kernel SHALL own app-icon generation

A single workspace package `@opentray/icon` (`packages/icon`) SHALL own the app-icon generation kernel: glyph construction, foreground analysis and composition, squircle tiling, platform encoding (ICNS, ICO, Linux PNG), the default glyph icon generator, and their cache identity. The Vite plugin, create-opentray core, and the runtime daemon SHALL consume this kernel rather than carrying their own copies of squircle, composition, or encoder logic. The kernel SHALL NOT depend on sharp or any libvips-bound native module; its image stack SHALL be WebAssembly-based so the same code path runs in Node, Bun, and browsers.

#### Scenario: Three consumers share one implementation

- **GIVEN** the Vite plugin, create-opentray core, and the runtime daemon each generate app icons
- **WHEN** their imports are inspected
- **THEN** every squircle, composition, glyph, and encoding path resolves into `@opentray/icon`
- **AND** no duplicate pipeline implementation exists in the consumer packages

#### Scenario: Kernel installs without native image dependencies

- **GIVEN** a consumer installs `@opentray/icon` through a normal package manager
- **WHEN** the dependency tree is inspected
- **THEN** no sharp or libvips-bound package is required for icon generation
- **AND** generation works on a machine with no compiler toolchain

### Requirement: Glyph defaults SHALL follow the continuous-curvature squircle standard

The default glyph generator SHALL render the application name's first character onto a tile whose shape uses the continuous-curvature (superellipse) squircle path, matching the tiling parameters of the shared kernel's brand-icon path. The generator SHALL emit both a full-canvas variant and the macOS best-practice content variant (content scaled inside the transparent canvas) and encode platform-standard assets from them: an ICNS with explicit tagged representations at 72 DPI density, an ICO with the shared size ladder, and Linux theme PNGs. Text rendering SHALL use an explicit font ladder — an embedded default family, then fonts discovered from the operating system supplied as explicit buffers — because system-font autoloading is unavailable in the WebAssembly rasterizer; text SHALL never be silently dropped.

#### Scenario: Squircle standard across generators

- **GIVEN** a default glyph icon and a brand-source icon generated by the shared kernel
- **WHEN** their tile geometry is compared
- **THEN** both use the same continuous-curvature tile parameters
- **AND** the glyph tile does not regress to a plain rounded rectangle

#### Scenario: macOS variant carries platform margins

- **GIVEN** a generated default glyph icon
- **WHEN** the macOS variant is inspected
- **THEN** the tile content occupies the platform content size centered on the transparent canvas
- **AND** ICNS representations carry explicit density metadata

#### Scenario: Font ladder renders uncovered scripts

- **GIVEN** a first character not covered by the embedded default font
- **WHEN** the glyph is rasterized on a machine whose system fonts cover it
- **THEN** the discovered system font renders the character via explicit font buffers
- **AND** no rasterization silently omits the text layer

### Requirement: Kernel outputs SHALL carry full cache identity

Generated asset sets SHALL be cached under an identity that includes the source bytes, the generator implementation identity, the rendering recipe version, the encoder and rasterizer stack versions, and every output path. A change in any identity component SHALL invalidate the cache and regenerate; an unchanged identity SHALL reuse prior outputs without re-running generation.

#### Scenario: Implementation change invalidates prior outputs

- **GIVEN** assets generated by an earlier kernel implementation
- **WHEN** generation runs with a changed implementation or recipe identity
- **THEN** assets are regenerated and the cache records the new identity

#### Scenario: Unchanged identity skips generation

- **GIVEN** assets generated for an identity
- **WHEN** generation runs again with the same identity
- **THEN** the cached outputs are reused without re-running rasterization or encoding
